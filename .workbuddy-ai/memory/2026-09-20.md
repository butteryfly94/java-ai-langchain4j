# 2026-09-20

## 通读 ai-langchain4j-prd 项目并输出改进建议

范围：`java-ai-langchain4j`（Spring Boot 3.4.7 + langchain4j 1.20.0/beta30 的医院智能客服 RAG）、
`xiaozhi-ui`（Vue3 + Vite 前端）、`docker-compose.yml`（ES 8.14.3）。

### 项目现状（已确认）
- 两条对话链路共用一个入口 `POST /api/xiaozhi/chat`：`QueryComplexityRouter` 按复杂度路由到
  固定 RAG（`retrievalAugmentorXiaozhi`）或 Agentic RAG（工具 + MCP filesystem）。
- 检索链路：查询扩展 → kNN/BM25 双路 → RRF 融合 → 父块扩展 → gte-rerank，`RrfRerankAggregator` 自定义实现。
- 摄入链路：父子分块（1000/300），MinerU `_content_list.json` 走 `TableAwareSplitter` 表格感知切分；
  `IngestionStats.warnings` 作为静默失效闸门。
- 引用溯源：`CitationRecorder` + 流末尾 `---SOURCES---` 标记。
- 记忆：MongoDB `MongoChatMemoryStore`，两个助手共用 `chatMemoryProviderXiaozhi`（maxMessages=20）。

### 已提出的主要改进点
1. **低风险快修**：`rag.router.enabled=false` 时 `ChatController` 仍会注入 `QueryComplexityRouter`（被无条件创建的 `@Service`），
   会连带创建 `routerChatModel`，导致"关掉路由"并不能省掉那条链路；建议给 router 加 `@ConditionalOnProperty`。
2. **路由不看对话历史**：`QueryComplexityRouter` 是纯函数，`"那第二个呢？"` 这类指代追问必判错，且 `intent` 不随 `memoryId` 传递；
   建议把最近一轮 user message 拼进判定输入。
3. **MCP filesystem 指向 knowledge/**：写文件工具与索引目录同源，LLM 可篡改知识源；建议副本目录 + 只读白名单。
4. **查询扩展放大 rerank 成本**：`ExpandingQueryTransformer` 为每个变体各跑一路双检索，
   但 rerank 仍只对"用户原问题 vs 父块"打分（`resolveOriginalQuery`），变体收益与成本不匹配。
5. **混合检索退化为串行**：`HybridRetrievalService.retrieveFromBoth` 顺序调用 kNN/BM25 并注释说交给调用方并行，
   实际无人并行化；建议用虚拟线程/`CompletableFuture` 并行。
6. **IngestionController 无并发保护**：`ingestAll()` 先删后建索引，两个请求并发会删掉对方正在写的索引，
   摄入期间 `/chat` 也会命中空索引；建议加锁 + 重建后原子切换（别名切换）。
7. **引用与答案不同源**：固定链路把所有 rerank 父块登记为引用（含 LLM 实际未使用的）；
   agentic 链路登记 RRF 全量（`KnowledgeSearchTool` 未过滤）。建议只登记真正注入 prompt 的部分。
8. **测试基建**：14 个测试全是 `@SpringBootTest` 真连 ES/Mongo/MySQL/LLM，无 CI 可跑的纯单测；
   `IngestionController` 无鉴权即可重建索引（DoS 面）。
9. **工程卫生**：仓库根目录混入 `马亚平.docx`、`~$马亚平.docx`、`resume_render_after/`、`optimize_resume.py` 等无关文件；
   `java-ai-langchain4j/hs_err_pid16816.log`（JVM 崩溃日志）应删除。
10. **存在与注释矛盾的过时类**：`Assistant`/`MemoryChatAssistant`/`SeparateChatAssistant` 及其 Config 是教程遗留，
    但注释声称"注解式装配拿不到控制权"已被 langchain4j 1.20 支持（`SeparateChatAssistant` 仍在用 `@AiService`）；
    建议或删除、或补 `@Profile` 隔离为 demo。
11. **前端**：`convertStreamOutput` 对 `&<>` 做转义**晚于**其他地方；`onDownloadProgress` 每帧全量重解析 + 转义，
    长回答浪费；`v-html` 与来源卡片渲染均可行但建议改 Markdown 渲染。
12. **pdf2md.py 路径**：脚本在 `java-ai-langchain4j/tools/`，但 `PROJECT_DIR` 取的是 parent.parent，
    实际成 `java-ai-langchain4j/`；`application.properties` 中 `rag.knowledge-dir=knowledge` 是相对 CWD，
    从仓库根启动会指向错误的目录。

### 结论
项目整体设计质量高于常见 Demo：注释记录设计取舍、"静默失效显式化"（摄入 warnings）、
链路对称性（两条链路共用同一批检索 bean）是几个明显优于同类的点。
待办优先级建议：先修 1/6/2/3（正确性与安全），再处理 4/5（成本与延迟），最后做 9/10/11（工程卫生）。
